1. EXECUTIVE SUMMARY
============================================================

RESIK (Retribusi Elektronik & Sistem Informasi Kebersihan)
adalah web application untuk digitalisasi pengelolaan iuran
layanan persampahan BUMDes Makmur Gedangan.

RESIK dibuat untuk menggantikan proses manual menggunakan
kartu pelanggan serta membantu BUMDes mengelola pelanggan,
lokasi layanan, tagihan, pembayaran, verifikasi, tunggakan,
komunikasi, laporan, dan administrasi secara terpusat.

Pelanggan tidak perlu menginstal aplikasi.

RESIK dapat dibuka melalui browser pada smartphone maupun
komputer.

Fokus utama RESIK:

1. Pelanggan dapat mengetahui apakah iuran bulan berjalan
   sudah dibayar atau belum.
2. Admin dapat memantau pembayaran dan tunggakan.
3. Pelanggan dapat membayar melalui tunai, transfer, atau QRIS.
4. Pelanggan dapat mengunggah bukti pembayaran.
5. Admin dapat memverifikasi pembayaran.
6. Sistem menghasilkan bukti pembayaran digital.
7. Sistem mendeteksi tunggakan otomatis.
8. Admin/petugas dapat mengingatkan pelanggan melalui WhatsApp.
9. Admin dapat mengirim broadcast.
10. Satu pelanggan dapat memiliki beberapa lokasi layanan.
11. Super Admin dapat mengatur konfigurasi aplikasi tanpa
    mengubah source code.
12. Semua aktivitas penting tercatat dalam audit log.

4. MASALAH YANG DISELESAIKAN
============================================================

Masalah saat ini:

1. Kartu pelanggan manual dapat hilang.
2. Kartu dapat rusak.
3. Kartu dapat lupa diisi petugas.
4. Pelanggan sulit mengetahui status pembayaran bulan berjalan.
5. Admin sulit memantau pelanggan yang belum membayar.
6. Tunggakan sulit dipantau secara terpusat.
7. Rekap pembayaran masih membutuhkan pekerjaan manual.
8. Data pelanggan belum sepenuhnya terpusat.
9. Informasi BUMDes belum terintegrasi secara digital.
10. Satu pelanggan dapat memiliki rumah sekaligus toko/usaha.
11. Perubahan rekening, tarif, wilayah, kontak, dan konfigurasi
    seharusnya tidak membutuhkan perubahan kode aplikasi.
12. BUMDes membutuhkan cara praktis mengingatkan pelanggan
    yang menunggak.

158. DEVELOPMENT PRINCIPLES
============================================================

1. Jangan hardcode konfigurasi BUMDes.
2. Gunakan Supabase sebagai sumber data utama.
3. Gunakan RLS.
4. Validasi permission di backend.
5. Jangan percaya validasi frontend saja.
6. Jangan menyimpan PIN plaintext.
7. Jangan menghapus transaksi keuangan secara permanen.
8. Semua aktivitas penting dicatat.
9. Semua nominal menggunakan tipe numeric/decimal yang sesuai.
10. Nomor rekening menggunakan TEXT.
11. Nomor HP menggunakan TEXT.
12. ID dibuat server-side.
13. Tagihan tidak boleh duplikat.
14. Pembayaran tidak boleh double.
15. Sistem harus mobile-first.
16. UI menggunakan bahasa Indonesia.
17. Informasi kosong tidak menghasilkan tombol kosong.
18. Fitur opsional tidak boleh merusak workflow utama.
19. Data histori harus dipertahankan.
20. Sistem harus siap berkembang.

============================================================
159. IMPORTANT BUSINESS RULES
============================================================

RULE 1:
Satu customer dapat mempunyai banyak service location.

RULE 2:
Satu service location hanya mempunyai satu tagihan untuk
satu periode.

RULE 3:
Tagihan yang melewati jatuh tempo dan belum lunas menjadi
OVERDUE.

RULE 4:
Pembayaran transfer/QRIS harus diverifikasi sebelum
dianggap PAID.

RULE 5:
Pembayaran yang sudah PAID tidak boleh dibuat ulang
secara normal.

RULE 6:
Customer hanya melihat datanya sendiri.

RULE 7:
Rekening aktif dapat digunakan untuk pembayaran.

RULE 8:
Rekening nonaktif tidak ditampilkan untuk pembayaran baru.

RULE 9:
Histori transaksi tidak boleh berubah hanya karena
rekening dinonaktifkan.

RULE 10:
Nomor rekening dapat dicopy.

RULE 11:
Jika nomor WhatsApp kosong, tombol reminder tidak muncul.

RULE 12:
WhatsApp MVP menggunakan wa.me dan bukan API otomatis.

RULE 13:
Sistem tidak boleh mengklaim WhatsApp telah terkirim
jika hanya membuka wa.me.

RULE 14:
Super Admin dapat menambah Admin dan Petugas.

RULE 15:
Role dan permission harus dapat dikembangkan.

RULE 16:
RW dan RT harus configurable.

RULE 17:
Tarif harus configurable.

RULE 18:
Jatuh tempo harus configurable.

RULE 19:
Media sosial harus configurable.

RULE 20:
Nama bank dan rekening harus configurable.
